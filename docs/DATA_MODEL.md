# Data model (D1 / SQLite)

Source of truth: `packages/db/src/schema.ts`. Migrations: `packages/db/migrations` (generated by drizzle-kit).

## Conventions
- IDs: text, `prefix_<20 hex>` (`newId('ord')`). Seed rows use readable ids (`city_sahiwal`, `var_matar_1000`).
- Money: integer PKR. Timestamps: ISO UTC text. Delivery date: `YYYY-MM-DD` (Asia/Karachi).
- Snapshots: orders copy names, labels, prices and the area name so later edits never change history.

## Tables
| Table | Purpose | Key columns |
|---|---|---|
| `cities` | Cities we sell in | `slug` unique, `is_active` |
| `delivery_areas` | Areas per city with delivery fee | `city_id`, `delivery_fee_pkr`, `is_active` |
| `categories` | Shop categories | `slug`, `image_key`, `sort_order`, `is_active` |
| `products` | Catalog items | `category_id`, `slug`, `status` (draft/active/archived), `badge`, `image_keys` JSON |
| `product_variants` | Sizes/packs with base price | `product_id`, `label`, `sku` unique, `price_pkr` |
| `inventory` | Per variant **per city**: availability, stock, daily cap, price override | PK (`variant_id`,`city_id`), `stock_qty` null = made to order, `daily_limit` null = no cap |
| `customers` | One row per phone | `phone` unique (03XXXXXXXXX) |
| `orders` | Order header + address snapshot + totals | `number` unique (PP-000123), `delivery_date`, `status`, `cod_collected`, `rider_id` |
| `order_items` | Lines with price snapshot | `variant_id`, `qty`, `delivery_date` (denormalised for limits/prep list) |
| `order_status_history` | Every status change | `order_id`, `status`, `by_email` |
| `riders` | Delivery riders | `phone` |
| `admin_users` | Who may use admin (matched to Access email) | `email` unique, `role` owner/staff/rider |
| `settings` | Key → JSON value | keys: cutoffHour, deliveryByLabel, maxDaysAhead, minOrderPkr, whatsappNumber, instagramHandle, alertEmails |
| `counters` | Monotonic counters | `order_number` |
| `audit_log` | Admin actions | `actor_email`, `action`, `entity`, `entity_id`, `data` |
| `notify_subscribers` | "Notify me" for deals/launches | unique (`phone`,`topic`) |

## Invariants
- A variant is **sellable** in a city iff: product `active`, variant active, inventory row exists with
  `is_available`, effective price > 0, and (`stock_qty` is null or ≥ qty), and daily limit not exceeded.
- Effective price = `inventory.price_override_pkr ?? product_variants.price_pkr`.
- `orders.status` changes only through `ORDER_TRANSITIONS`; each change inserts `order_status_history`.
- Cancelling an order adds tracked stock back.

## Adding a city
Insert `cities` (inactive), add `delivery_areas`, add `inventory` rows for the variants you sell there, then
activate the city. No schema change. Storefront city picker is ROADMAP P6.
